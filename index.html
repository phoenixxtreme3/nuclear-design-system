Design tokens & components for the LoveLocal app

Synced from the Nuclear v2.0 Figma file. This release covers base tokens and one component, Navigation Header.

Overview

Nuclear is LoveLocal's design system — the shared colors, type, spacing and components behind the B2C app. This first release covers base tokens and the Navigation Header component, pulled directly from the Nuclear v2.0 Figma file.

Governance

  • Source of truth — Figma is upstream. Changes start there, get design sign-off, then sync into this repo.
  • Versioning — semver. Patch = corrections, no visible change. Minor = new tokens/components, additive. Major = renamed/removed tokens or breaking changes.
  • Contributing — propose in Figma first, then open a PR here updating source and docs together. @design-systems is a required reviewer.
  • Deprecation — marked one minor version before removal, with its replacement noted, removed at the next major version.

Full write-up in the top-level README.

Colors

One theme today. brand-primary is the single accent, with a small accent ramp for emphasis/subtle states; everything else is a neutral content/background/border ramp plus one inverse surface used by components like the header that need a dark treatment without a full dark theme. nav-* tokens are role aliases for the top bar and bottom tab bar.

Typography

var(--font-sans) — "Lato", "Helvetica Neue", Helvetica, Arial, sans-serif (Lato is Nuclear's primary family in Figma; Helvetica/Arial are the web-safe fallback). Every text style used across the app's navigation surfaces, each named after its source Figma text style.

Spacing, radius & size

A spacing scale, three corner radii, and the default icon size.

Icons

Exported directly from Nuclear v2.0 — the Navigation Header glyphs plus the full Shop-type icon set used in the category filter. Each is fill="currentColor", inheriting whatever text color it sits in.

Usage guidelines

Do keep the greeting to one short word ("Home"); use dark-background=true only on an actually dark section; truncate the address line rather than wrapping it.

Don't restyle the search field's radius or fill outside the token values; don't add more than one primary action to the status cluster.

Accessibility

  • The greeting is a real <button>, not a clickable <div>.
  • Search uses <form role="search"> with a visually-hidden <label>.
  • content-secondary on bg-surface-subtle is 5.2:1; content-on-color on bg-inverse is 15.9:1 — both pass WCAG AA.
  • Search and voice-search icon buttons carry an aria-label.
